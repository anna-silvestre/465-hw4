PROMPT: what do standard iptables commands look like

RESPONSE: iptables commands generally follow this structure:

sudo iptables [OPTIONS] [CHAIN] [MATCHES] [TARGET]

It's a Linux command-line utility for configuring the kernel's IPv4 firewall.

1. Basic commands
Command

Purpose

iptables -L

List firewall rules

iptables -L -n -v

List rules with details, without DNS resolution

iptables -S

Display rules as commands

iptables -F

Flush (delete) all rules

iptables -N MYCHAIN

Create a custom chain

iptables -X MYCHAIN

Delete a custom chain

iptables -Z

Reset packet counters

2. Adding rules
The general syntax is:

iptables -A CHAIN [MATCH CONDITIONS] -j TARGET

-A: Append a rule to a chain.

-I: Insert a rule (at the beginning by default).

-D: Delete a rule.

-p: Specify protocol.

-s: Specify source IP.

-d: Specify destination IP.

--dport: Specify destination port.

-j: Specify what action to take.

Examples
Allow SSH traffic (port 22):

sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

Block traffic from a specific IP:

sudo iptables -A INPUT -s 192.168.1.100 -j DROP

Allow HTTP traffic (port 80):

sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT

Block all incoming ICMP (ping) traffic:

sudo iptables -A INPUT -p icmp -j DROP

Allow traffic from a particular network:

sudo iptables -A INPUT -s 192.168.1.0/24 -j ACCEPT

3. Understanding chains
There are three particularly important built-in chains:

Chain

Purpose

INPUT

Traffic coming into your machine

OUTPUT

Traffic leaving your machine

FORWARD

Traffic passing through your machine

There are also three common targets:

Target

Behavior

ACCEPT

Allow the packet

DROP

Silently discard the packet

REJECT

Discard and send an error response

4. A more complete example
Suppose you wanted to configure a basic firewall:

# Flush existing rules
sudo iptables -F

# Allow loopback traffic
sudo iptables -A INPUT -i lo -j ACCEPT

# Allow established connections
sudo iptables -A INPUT -m conntrack \
    --ctstate ESTABLISHED,RELATED -j ACCEPT

# Allow SSH
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Allow HTTP and HTTPS
sudo iptables -A INPUT -p tcp -m multiport \
    --dports 80,443 -j ACCEPT

# Drop everything else coming in
sudo iptables -P INPUT DROP

Important Be careful when changing firewall policies over SSH. If you set the default INPUT policy to DROP before allowing your SSH connection, you can lock yourself out.

5. Useful concepts to recognize
A few additional things you'll commonly encounter:

# Match established connections
-m conntrack --ctstate ESTABLISHED,RELATED

# Match a network interface
-i eth0

# Match a source port
--sport 8080

# Match multiple ports
-m multiport --dports 80,443,8080

# Set default chain policy
-P INPUT DROP
-P OUTPUT ACCEPT
-P FORWARD DROP

One important distinction: -A adds a rule to the end of a chain, whereas -I inserts it at the beginning. Since iptables evaluates rules in order, this can make a substantial difference.
