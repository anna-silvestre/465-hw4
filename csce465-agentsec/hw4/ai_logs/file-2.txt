I am conducting a lab in which on a virtual ubuntu 24.02 image I'm attempting to observe and report a cyber incident. To do this I am building a docker with three containers, an agent-node, web-lab, and mock-c2. I already have a docker compose file. What else do I need to run this docker.
Since you're running this lab on a virtual Ubuntu 24.04 machine and already have a docker-compose.yml defining three containers (agent-node, web-lab, and mock-c2), you're most of the way there.

You'll need a few things installed and configured before you can bring the environment online.

I'll break this down into prerequisites, setup, and execution.

1. Install the required software
On your Ubuntu VM, you'll need:

Install Docker Engine and Compose
First, update Ubuntu:

sudo apt update
sudo apt upgrade -y

Install prerequisites:

sudo apt install -y ca-certificates curl gnupg git python3 python3-pip tcpdump

Add Docker's official repository:

sudo install -m 0755 -d /etc/apt/keyrings

sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
-o /etc/apt/keyrings/docker.asc

sudo chmod a+r /etc/apt/keyrings/docker.asc

Add the repository:

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

Install Docker and its Compose plugin:

sudo apt update

sudo apt install -y docker-ce docker-ce-cli containerd.io \
docker-buildx-plugin docker-compose-plugin

Start Docker:

sudo systemctl enable --now docker

Verify the installation:

sudo docker --version
sudo docker compose version

You should see version information for both.

Optionally, allow your user to run Docker without sudo:

sudo usermod -aG docker $USER

Log out and back in for the group change to take effect.

2. Organize your project directory
I recommend keeping all your lab files together.

For example:

cyber-incident-lab/
│
├── docker-compose.yml
│
├── agent-node/
│   ├── Dockerfile
│   └── ...
│
├── web-lab/
│   ├── Dockerfile
│   └── ...
│
├── mock-c2/
│   ├── Dockerfile
│   └── ...
│
├── logs/
│
└── captures/
The three individual directories would contain the Dockerfiles and any scripts, configuration files, or application files needed to build their respective containers.

Important: Having a Docker Compose file does not necessarily mean Docker has everything it needs to build your containers.

Your Compose file needs to specify either:

A build: configuration pointing to a directory containing a Dockerfile.

An image: configuration referencing an existing Docker image.

For example:

services:
  agent-node:
    build: ./agent-node

  web-lab:
    build: ./web-lab

  mock-c2:
    build: ./mock-c2

3. Build and start the containers
Navigate to the directory containing your Compose file:

cd ~/cyber-incident-lab

Build the images:

sudo docker compose build

Start all three containers:

sudo docker compose up -d

The -d flag runs the containers in the background.

Check their status:

sudo docker compose ps

You should see all three services listed.

4. Verify that the environment works
Before conducting your incident simulation, verify that all three containers are operating correctly.

Check container logs:

sudo docker compose logs

Check an individual container:

sudo docker compose logs agent-node
sudo docker compose logs web-lab
sudo docker compose logs mock-c2

Open an interactive shell inside a container:

sudo docker compose exec agent-node bash

If the container doesn't have Bash installed, use:

sudo docker compose exec agent-node sh

Inspect the Docker network:

sudo docker network ls

Docker Compose normally creates a shared network for the services, allowing them to communicate using their service names.

For example, agent-node could reach web-lab using its service name as the hostname, assuming they share a network.
